5 Ways to Add SVG to a Web Page (and When to Use Each)

SVG is the best format for logos, icons and illustrations on the web, but there is more than one way to put it on a page. Each method affects styling, caching, accessibility and performance differently. Here are the five main options and when to choose each.

1. The <img> tag

<img src="logo.svg" alt="Company name" width="160" height="40">

The simplest approach, and often the right one.

  • Pros: easy, cached by the browser, works with lazy loading, keeps HTML clean.
  • Cons: you cannot change the SVG's colours with your page's CSS, and scripts inside the SVG do not run (which is also a security benefit).
  • Use it for: logos, illustrations and any graphic you do not need to restyle.

Always include alt text and width and height attributes to prevent layout shift while the page loads.

2. Inline SVG

<svg viewBox="0 0 24 24" width="24" height="24" aria-hidden="true">
  <path d="M12 2l3 7h7l-5.5 4 2 7L12 16l-6.5 4 2-7L2 9h7z" fill="currentColor"/>
</svg>

The SVG code is placed directly in the HTML.

  • Pros: full CSS control (colours, hover effects, animation), no extra HTTP request, can be scripted.
  • Cons: not cached separately, so repeating a large SVG on many pages increases page weight; HTML becomes harder to read.
  • Use it for: icons that change colour on hover or with themes, animated graphics and interactive charts.

Using fill="currentColor" makes the icon take the text colour of its parent, which is ideal for buttons and links.

3. CSS background-image

.badge { background: url("badge.svg") no-repeat center / contain; }
  • Pros: keeps decorative images out of the HTML, cached, easy to swap with media queries.
  • Cons: not accessible to screen readers (fine for decoration, bad for meaningful images) and not styleable from the page.
  • Use it for: decorative patterns, backgrounds and ornaments.

Modern CSS also offers mask-image, which lets you use an SVG as a shape and colour it with background-color — a neat way to recolour icons without inlining them.

4. The <object> or <iframe> element

<object data="diagram.svg" type="image/svg+xml">Diagram of the process</object>
  • Pros: the SVG keeps its own scripts and interactivity, and is cached.
  • Cons: styling from the parent page is not possible, and it behaves more like an embedded document than an image.
  • Use it for: self-contained interactive SVGs, such as some maps and diagrams.

5. SVG sprites with <use>

<svg width="24" height="24"><use href="icons.svg#search"></use></svg>

Many icons are stored as <symbol> elements in one file and referenced by ID.

  • Pros: one cached file for an entire icon set, while still allowing currentColor styling.
  • Cons: external sprites must be served from the same origin (or with CORS), and setup is a little more involved.
  • Use it for: sites with many icons used across many pages.

Which one should you choose?

NeedBest method
Simple logo or illustration<img>
Icon that changes colourInline SVG or sprite
Large icon setSprite with <use>
Decorative backgroundCSS background or mask
Interactive standalone graphic<object> or inline

Performance and accessibility tips

  • Optimise SVGs before use — see How to Reduce SVG File Size.
  • For meaningful inline SVGs, add role="img" and a <title>; for decorative ones, use aria-hidden="true".
  • Avoid inlining very large illustrations on every page; use <img> so the browser can cache them.
  • Never inline SVG files uploaded by users without sanitising them, as they can contain scripts.

Summary

Use <img> by default, inline SVG when you need CSS control, sprites for large icon sets, and CSS backgrounds for decoration. Matching the method to the job gives you sharp graphics, good caching and accessible pages.
