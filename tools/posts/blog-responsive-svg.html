Vectors are resolution-independent, so you might expect every SVG to be responsive automatically. In practice, many SVGs either overflow small screens, sit at a fixed size or leave strange empty space. The fix is understanding a few attributes and CSS rules.

Rule 1: Always have a viewBox

The viewBox attribute defines the SVG's internal coordinate system — for example viewBox="0 0 400 200" means the drawing is 400 units wide and 200 units tall. With a viewBox, the browser can scale the drawing to any size while keeping proportions. Without one, the SVG cannot scale its contents and is effectively fixed-size.

If your SVG has width and height but no viewBox, add one using the same numbers: width="400" height="200" becomes viewBox="0 0 400 200". See The SVG viewBox Explained for details.

Rule 2: Let CSS control the size

For a fluid graphic that fills its container:

.hero-art { width: 100%; height: auto; }

This works for both <img src="art.svg"> and inline <svg>. Keep the width and height attributes in the markup too — browsers use their ratio to reserve the right amount of space before the image loads, which prevents layout shift.

To stop a graphic from becoming huge on wide screens, add a maximum:

.logo { width: 100%; max-width: 240px; height: auto; }

Rule 3: Understand preserveAspectRatio

When the space you give an SVG has a different shape from its viewBox, preserveAspectRatio decides what happens. The default, xMidYMid meet, scales the drawing to fit entirely inside the box and centres it, leaving empty space if needed.

  • xMidYMid slice — fills the whole box and crops the overflow, like object-fit: cover. Good for background illustrations.
  • xMinYMid meet — fits, but aligns to the left instead of centre.
  • none — stretches the drawing to fill the box, distorting it. Occasionally useful for decorative waves and dividers that should span the full width.

Rule 4: Adjust detail for small screens

A detailed illustration that looks great on a desktop can become an unreadable blur of tiny shapes on a phone. Options include:

  • Swap files with the <picture> element, serving a simpler SVG to narrow screens: 
    <picture>
  <source media="(max-width: 600px)" srcset="map-simple.svg">
  <img src="map-detailed.svg" alt="Store locations">
</picture>
  • Hide elements with CSS in an inline SVG, for example removing labels below a certain width.
  • Use media queries inside the SVG. A standalone SVG file can contain a <style> block with media queries that respond to the SVG's own rendered size — handy for logos that switch to a compact mark when small.

Rule 5: Keep text readable

Text inside an SVG scales with the graphic. A label that is 14 units tall in a 1200-unit-wide chart becomes tiny on a 360-pixel phone screen. For charts and diagrams, consider placing text in HTML around the SVG, or providing a narrower layout for mobile.

Rule 6: Mind stroke widths

Strokes scale along with the drawing. A 2-unit outline might be crisp on desktop and nearly invisible on mobile. Use vector-effect: non-scaling-stroke on lines that should keep a constant on-screen thickness.

Responsive SVG checklist

  1. The SVG has a viewBox.
  2. Width and height attributes are present for layout stability.
  3. CSS sets width: 100% (or a fixed size) and height: auto.
  4. preserveAspectRatio matches the desired fit.
  5. Detail and text are tested at phone width.
  6. The file is optimised so it loads quickly on mobile networks.

Making traced images responsive

SVGs created with our PNG to SVG converter include a viewBox matching the original image's dimensions, so they scale out of the box. Just apply the CSS from Rule 2.

Summary

A viewBox plus CSS sizing makes almost any SVG responsive. Add preserveAspectRatio for control over fit and cropping, simplify detail for small screens, and test text and strokes on a real phone before publishing.
