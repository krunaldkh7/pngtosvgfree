When you need to draw graphics in a web browser — charts, diagrams, games, editors — two native technologies are available: SVG and the HTML <canvas> element. They can produce similar-looking results, but they work in fundamentally different ways. Choosing the right one saves a lot of effort.

How SVG works: retained mode

SVG is a retained-mode graphics system. Every shape is an element in the page's DOM, like a paragraph or a button. The browser remembers each element and redraws it automatically when something changes. You can select shapes with CSS, attach event listeners, and inspect them in developer tools.

How canvas works: immediate mode

Canvas is an immediate-mode system. It gives you a bitmap — a grid of pixels — and a JavaScript API to draw on it. Once drawn, shapes are just pixels; the browser does not remember them. To move something, you clear the canvas and redraw everything. Canvas supports a 2D API and, through WebGL and WebGPU, hardware-accelerated 3D.

When SVG is the better choice

  • Icons, logos and illustrations — static or lightly animated graphics.
  • Charts and dashboards with up to a few thousand elements, especially when they need tooltips, hover effects and accessibility.
  • Diagrams and flowcharts that users click and explore.
  • Maps with interactive regions.
  • Graphics that must be crisp at every zoom level and printable.

When canvas is the better choice

  • Games and fast animations with many moving objects.
  • Large data visualisations such as scatter plots with hundreds of thousands of points.
  • Image editing and pixel manipulation — filters, painting, photo editors.
  • Real-time effects such as particle systems and video processing.
  • 3D graphics via WebGL or WebGPU.

Using both together

Many applications combine them. A mapping app might draw thousands of data points on a canvas and overlay interactive SVG labels and controls. A chart library may render to SVG by default and switch to canvas for very large datasets. Some tools also render SVG into a canvas to export images.

Accessibility considerations

SVG content can be given roles, titles and descriptions, and text inside SVG can be read by screen readers. Canvas content is invisible to assistive technology, so you must provide alternatives — fallback content inside the canvas element, ARIA labels, or a parallel HTML representation. See How to Make SVG Graphics Accessible.

A simple rule of thumb

  • Fewer than a few thousand objects and need interaction, accessibility or crisp scaling? SVG.
  • Thousands of objects, frequent full redraws or pixel-level work? Canvas.

Summary

SVG is a scalable, styleable, accessible graphics model built into the DOM — ideal for icons, charts, diagrams and maps. Canvas is a fast pixel surface — ideal for games, huge datasets and image processing. Pick based on object count, interactivity and accessibility needs, and do not hesitate to combine them.
